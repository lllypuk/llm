# v0.6.0: маршрут OCR — Yandex Vision OCR

## Overview

Потребитель — DPP, эпик E47.1 (`../digital-property-passport/docs/specs/E47-ocr-memory.md`): текст каждого кадра и страницы скана через Yandex Vision OCR, модель `page`. OCR — третий контракт библиотеки после чата и речи и строится **по образцу речи v0.5.0**: свой интерфейс плеча, свой раздел конфига, свой маршрут и цикл попыток на общих паузах, сроке и классах отказа. Чатовый `Router`/`Provider` и речь не меняются.

Результат — релиз v0.6.0: CHANGELOG, раздел README. Тег ставит диспетчер после мержа, не воркер.

API Yandex Vision OCR (сверено с документацией 25.09.2026):
- `POST https://ocr.api.cloud.yandex.net/ocr/v1/recognizeText`; заголовки `Authorization` (схема из `CredentialSource`), `x-folder-id`, **`x-data-logging-enabled: false`** — в кадрах чеки и документы людей, логирование у провайдера выключено всегда;
- тело `{"mimeType": "JPEG"|"PNG", "languageCodes": ["ru","en"], "model": "page", "content": "<base64>"}`;
- ответ — `result.textAnnotation.fullText` (обёртку `result` сверить с примером ответа в quickstart Vision OCR; тест держит документированную форму);
- пределы: JPEG, PNG, PDF в одну страницу; кадр до 20 Мп; файл до 10 МБ; синхронный лимит — 1 запрос в секунду;
- тарификация — за страницу (0,1321 ₽ с НДС за единицу).

## Development Approach

- **Testing approach**: Regular — код, затем тесты в той же задаче.
- Задача целиком, затем следующая; тесты зелёные перед переходом.
- Каждая задача — с тестами; адаптер — `httptest`, как `yandex/speech_test.go`; маршрут — фейковый распознаватель, как `speech_route_test.go`.
- Коммиты — по-русски, `feat:`/`docs:`; комментарии по правилам из `~/.claude/CLAUDE.md` (док-комментарий одной строкой, внутри тела — только где код противоречит ожиданию).
- Обратная совместимость: конфиг без раздела `ocr` разбирается как раньше, `ResolveOCR` незаявленной задачи — `false` без ошибки.

## Решения

1. **Свой контракт, а не расширение `Provider` или `Transcriber`** — так же, как речь в v0.5.0: у OCR свои вход (кадр), выход (текст и страницы) и единица тарифа.
2. **PDF в библиотеку не идёт.** `OCRRequest` принимает JPEG и PNG; растеризацию делает потребитель (у DPP — `pdftoppm`, потолок страниц — его правило). Одностраничный PDF API умеет, но единица «кадр» проще и одна на все плечи.
3. **Паузы между вызовами — дело потребителя.** Лимит 1 запрос/с — квота облака, а не процесса; библиотека переживает `429` штатным классом отказа и паузой, а темп задаёт очередь потребителя.
4. **Отпечаток маршрута** — kind + model + языки + `ocrRouteVersion = "ocr/1"`, без имени плеча и тарифа (как `SpeechDescriptor.Fingerprint`): потребитель пишет его в `model_version`.
